1. 오늘 배운 내용

   - JDBC는 SQL Mapper와 ORM(JPA) 둘로 나뉨 SQL Mapper는 MyBatis같은 게 있고 
   응답 결과를 객체로 변환해주지만, SQL을 직접 작성해야 하고,<br>
   JPA는 DB와 매핑해두면 SQL을 알아서 작성하고 진행하지만 깊이있는 학습이 필요함ㅠ
   - 드라이버 매니저를 통해서 커넥션을 가져와야 한당
   - 커넥션을 연결하는 과정
   1. 어플리케이션에서 DB에 커넥션 연결을 요청함 
   2. 가지고 있는 드라이버들을 다 DB에 던져봄 (MySql, h2 ...)
   3. 맞는 걸 찾으면 그걸로 연결함

   - Connection의 역할은 그 DB와 설정 내용을 바탕으로 연결한 통로(무전기?)라고 생각하면 됨
   -> 이걸로 커밋, 롤백, 종료 등 여러가지 동작을 수행할 수 있음
   - preparedStatement는 statement의 자식으로 미리 벨류를 파라미터로 바인딩 할 수 있는 쿼리를 준비해둔 다음
   나중 설정 단계 때 setInt() 등 메서드를 통해서 바인딩이 가능하다 <br>
   그리고 SQL injection 공격을 방지하기 위해 씀
   - prepareStatement를 connection에서 가져오고 여러 설정 후 **.executeUpdate()를 통해서 pstmt 한정 커밋이 가능
   <br> -> 이 말은 설정된 것을 바탕으로 한 번에 실행하겠다는 뜻
   - 그 후 커넥션을 통해 뭘 커밋하든 DB조작이 끝났으면 먼저 사용한 것의 역순으로 자원들을 닫아줘야 함 <br>
   ex) getConnetion -> con.getPreraedStatement() -> ~~ -> pstmt.close() -> con.close()
   <br> 여기서 예외가 발생하면 후의 자원 회수 메서드가 동작하지 않을 수 있으니 예외처리를 잘 해야 한다
   ```

           if (rs != null) {
               try {
                rs.close();
               } catch (SQLException e) {
                   log.info("error", e);
               }
           }

           if (stmt != null) {
               try {
                   stmt.close();
               } catch (SQLException e) {
                   log.info("error", e);
               }
           }
        
           if (con != null) {
               try {
                   con.close();
               } catch (SQLException e) {
                   log.info("error", e);
               }
           }
    
   ```
